# aegis-desktop by-features Reorganization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reorganize `apps/desktop/aegis-desktop/src` so `data/`, `pages/`, and `components/` are grouped by feature (`features/<name>/{data,pages,components}`) plus `shared/` for cross-cutting (`api`, `query`, `BootstrapLog`). No behavior change.

**Architecture:** This is a single-commit, mechanical structural refactor. Eight feature folders are created and populated by moving existing files; import paths are rewritten to match. Cross-cutting modules (`api/`, `QueryProvider` + `queryKeys`, `BootstrapLog`) move to `shared/`. `routes/` stays flat (TanStack Router requirement) — route files become thin pass-throughs that import pages from the new feature folders. `main.tsx` is rewired to import from `shared/` and `features/app/components/`. The `queryKeys` namespace is preserved (not reshuffled). All existing tests move alongside their source with updated import paths.

**Tech Stack:** Tauri desktop app, React 19 + TypeScript, TanStack Router, TanStack Query v5, MUI v9 (via `@aegis/ui/mui`), Vitest + Testing Library. Workspace package `@aegis/ui`. App package `aegis-desktop`.

**Spec:** [2026-08-16-aegis-desktop-by-features-reorganization-design.md](../specs/2026-08-16-aegis-desktop-by-features-reorganization-design.md) — read it first.

## Global Constraints

These constraints apply to every task. If a task contradicts a constraint, the constraint wins.

- **Single commit**: this entire refactor lands as ONE git commit at the end of Task 12. Intermediate tasks accumulate changes in the working tree without committing.
- **Pure structural refactor**: no behavior changes, no new features, no test rewrites. File contents move byte-for-byte except for import-path updates.
- **`routes/` stays flat**: TanStack Router's file-routes directory remains `src/routes/`. Only the import paths inside route files change. `routeTree.gen.ts` is regenerated by the router plugin on next dev run.
- **Barrel rule**: `features/<name>/index.ts` exports only **data hooks**. Components and pages are imported directly by path.
- **Page vs component**: file consumed by a route file → `pages/`. File consumed by another component/page → `components/`. Layouts (`AppLayout`, `ProjectWorkspaceLayout`) keep their existing names (no `Page` suffix).
- **Page file naming**: PascalCase + `Page` suffix for routes: `LoginPage.tsx`, `UserListPage.tsx`, `ProjectListPage.tsx`, `SettingsPage.tsx`, `HomePage.tsx`, `BootstrapPage.tsx`, `ProjectDashboardPage.tsx`, `ProjectConfigurationPage.tsx`. Layouts retain their current names.
- **Data hook file naming**: camelCase matching the primary hook. Multiple hooks per file when they share an invalidation contract (e.g. `login.ts` holds `useLogin` + `useLoginDomain`).
- **`queryKeys.ts` shape preserved**: keys stay grouped as `auth.loginStatus`, `bootstrap.health`, `user.{current,domainIdentity,list}`, `project.{all,byCode}`, `product.all`. File moves to `shared/query/keys.ts`; namespace not refactored.
- **No `src/data/`, `src/pages/`, `src/components/`, `src/api/` left at top level after Task 12**. They are replaced by `src/features/` and `src/shared/`.
- **Verification command**: from repo root, run `pnpm --filter aegis-desktop typecheck` and `pnpm --filter aegis-desktop test`. Both must pass after Task 10 Step 14, Task 11 Step 11 / Step 12, and Task 12 Step 6. Intermediate tasks (1–9) intentionally leave the codebase in a broken intermediate state, so they do NOT run typecheck — running it would only show the pre-existing breakages from earlier tasks, not catch a new regression.
- **Test mock pattern preserved**: tests that mock Tauri commands use the existing helpers in `src/test/tauri-mock.ts` (`mockCommands({...})`, `httpError(status, code, message)`).
- **Existing tests are byte-identical**: assertions and rendered-output checks stay the same. Only `import` paths at the top of each test file change.

```ts
import { useMutation, useQueryClient } from "@tanstack/react-query";

import { api, type ApiError } from "../../../shared/api";
import { queryKeys } from "../../../shared/query";

// Login mutation. On success, invalidates the login-status probe so
// the auth-gated layout re-derives its auth state on the next render.
// The transport throws a structured `ApiError` on failure, which
// surfaces unchanged through `mutation.error`.
export function useLogin() {
  const qc = useQueryClient();
  return useMutation<void, ApiError, { code: string; password: string }>({
    mutationFn: (vars) => api.login(vars.code, vars.password),
    onSuccess: () =>
      qc.invalidateQueries({ queryKey: queryKeys.auth.loginStatus() }),
  });
}

// Domain-account login mutation. Same invalidation contract as
// `useLogin` — the post-login render path is identical regardless
// of which method landed the user.
export function useLoginDomain() {
  const qc = useQueryClient();
  return useMutation<void, ApiError, void>({
    mutationFn: () => api.loginDomain(),
    onSuccess: () =>
      qc.invalidateQueries({ queryKey: queryKeys.auth.loginStatus() }),
  });
}
```

`apps/desktop/aegis-desktop/src/features/auth/data/logout.ts`:

```ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { getAllWebviewWindows } from "@tauri-apps/api/webviewWindow";

import { api, type ApiError } from "../../../shared/api";

/**
 * Logout mutation. Clears the entire cache so no stale user data
 * leaks across the auth boundary — including the login-status probe
 * cache entry that `useLogin` / `useLoginDomain` invalidate. Also
 * closes every project workspace window (label-prefixed `project:`)
 * BEFORE clearing the cache, so workspace pages can't issue stale
 * fetches against a logged-out session.
 */
export function useLogout() {
  const qc = useQueryClient();
  return useMutation<void, ApiError, void>({
    mutationFn: () => api.logout(),
    onSuccess: async () => {
      // Close every project workspace window BEFORE clearing the
      // cache. Workspace windows have their own React tree and their
      // own query client — closing them first means the cached data
      // is never read again, and there is no ordering window during
      // which a workspace page could issue a stale fetch.
      //
      // The window enumeration is wrapped in try/catch so logout
      // still succeeds in environments where Tauri isn't available
      // (jsdom tests, future non-Tauri hosts): cache clearing is the
      // critical side effect, window cleanup is best-effort.
      try {
        const all = await getAllWebviewWindows();
        await Promise.all(
          all
            .filter((w) => w.label.startsWith("project:"))
            .map((w) => w.close()),
        );
      } catch {
        // Swallow — see comment above.
      }
      qc.clear();
    },
  });
}
```

```ts
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";

import {
  api,
  type ApiError,
  type UpdateUserBody,
  type UserView,
} from "../../../shared/api";
import { queryKeys } from "../../../shared/query";

/**
 * All users. Consumed by the drawer's member pickers. Default
 * `enabled: true` because the drawer is the only consumer and only
 * opens for root/admin, where the call always succeeds in practice.
 */
export function useListUsers(options?: { enabled?: boolean }) {
  return useQuery<UserView[], ApiError>({
    queryKey: queryKeys.user.list(),
    queryFn: () => api.listUsers(),
    enabled: options?.enabled ?? true,
  });
}

/**
 * Update an existing user. On success: invalidates the user list cache
 * so the management page reflects the new active state on the next
 * render. Also invalidates `user.current()` since the current user's
 * own row could be the one being updated by a sibling admin and the
 * `UserFooter` reads the same cache entry.
 */
export function useUpdateUser() {
  const qc = useQueryClient();
  return useMutation<
    UserView,
    ApiError,
    { code: string; body: UpdateUserBody }
  >({
    mutationFn: ({ code, body }) => api.updateUser(code, body),
    onSuccess: () => {
      qc.invalidateQueries({ queryKey: queryKeys.user.list() });
      qc.invalidateQueries({ queryKey: queryKeys.user.current() });
    },
  });
}
```

# Project workspace window for Aegis desktop

Date: 2026-08-16
Status: Approved (brainstorming)

## Goal

Open a project workspace in its own Tauri webview window at the URL
`/project/{project-code}`. The window reuses the same React app, the
same `HttpClient`, the same `@aegis/ui` providers, and the same
TanStack Router. It differs from the main window only in:

1. Sidebar header is the project code (not the app title).
2. Sidebar footer is a "Back to main" button that focuses the main
   window.
3. Sidebar menu has two items — Dashboard, Configuration — both
   rendered as placeholders.
4. Every project:* window is closed when the user logs out from the
   main window.
5. Theme and language changes in the main window propagate to every
   open workspace window immediately.

The feature lives entirely in `apps/desktop/aegis-desktop`. No
`src-tauri/` Rust changes. One capability entry added
(`core:window:allow-set-focus`) — `setFocus()` is called both from
the workspace window's "Back to main" footer button and from the
close-on-logout sweep. The existing `store:default` covers the
`settings.bin` store.

## Approach

A new pathless route segment `_project` lives alongside the existing
`_layout`. The `_project/route.tsx` performs the same auth guard and
reads the `:projectCode` URL param. Opening a project from the table
calls `WebviewWindow.new('project:<code>', { url: '/project/<code>' })`.
If a window with that label already exists, it is focused instead of
duplicated.

The workspace window loads the same Vite `index.html`, runs the same
`main.tsx`, and reuses every existing provider. The only new piece is
a small `SettingsSyncBridge` component that (a) hydrates theme + locale
from `tauri-plugin-store` on mount, and (b) listens for the
`aegis:settings-changed` event the main window emits when the user
changes them in Settings.

`useLogout` (in `src/data/user.ts`) extends its success handler to
iterate `getAllWebviewWindows()`, filter labels starting with
`project:`, and close each before clearing the query cache.

### Why one window per project (label prefix `project:`)

Tauri 2 allows multiple windows with different labels but only one
per label. Using `project:<code>` lets us:

- Identify "the workspace windows" with a single prefix filter for
  the close-on-logout sweep.
- Detect duplicates on open without a separate registry.
- Address a specific window directly when we ever need to navigate
  it from outside (e.g. deep-link a different page within the same
  project).

### Why frontend-only `WebviewWindow.new`

A Rust command would just call `WebviewWindowBuilder::new(...)`. The
JS call is one line shorter and avoids adding a Tauri command +
capability entry for a feature the frontend can do directly.

### Why store + event sync (not event-only)

A freshly-opened workspace window has no way to know what theme or
language the main window had at the moment of its birth if we use
events alone — the event already fired. Persisting to
`tauri-plugin-store` and reading on mount makes the cold-start case
work too.

### Close on logout

`src/data/user.ts` — extend the success handler:

```ts
import { getAllWebviewWindows } from "@tauri-apps/api/webviewWindow";

export function useLogout() {
  const qc = useQueryClient();
  return useMutation<void, ApiError, void>({
    mutationFn: () => api.logout(),
    onSuccess: async () => {
      // Close every project workspace window BEFORE clearing the cache.
      // The workspace windows do not share this query client; closing
      // them first means the cached data is never read again.
      const all = await getAllWebviewWindows();
      await Promise.all(
        all
          .filter((w) => w.label.startsWith("project:"))
          .map((w) => w.close()),
      );
      qc.clear();
    },
  });
}
```

The `UserFooter` (in `src/pages/UserFooter.tsx`) is unchanged — it
calls `useLogout().mutateAsync()` then `navigate({ to: "/login" })`.

The workspace windows have no logout button and no settings page, so
the only path that triggers `useLogout` is from the main window — the
close sweep runs in exactly one place.

```tsx
import React from "react";
import { Outlet, useNavigate, useParams } from "@tanstack/react-router";
import { Box, Button } from "@aegis/ui/mui";
import {
  Sidebar,
  type MenuItem,
  type SidebarProps,
} from "@aegis/ui";
import {
  Dashboard as DashboardIcon,
  Settings as SettingsIcon,
} from "@aegis/ui/icons";
import { useI18n } from "@aegis/ui/i18n";
import { getAllWebviewWindows } from "@tauri-apps/api/webviewWindow";

const DashboardMenuIcon = () => <DashboardIcon />;
const ConfigMenuIcon = () => <SettingsIcon />;

/**
 * Workspace window shell. Sidebar header is the project code; footer
 * is a button that focuses the main window; menu has Dashboard +
 * Configuration entries only.
 */
export function ProjectWorkspaceLayout() {
  const { t } = useI18n();
  const navigate = useNavigate();
  const { projectCode } = useParams({ strict: false }) as {
    projectCode: string;
  };
  const [sidebarOpen, setSidebarOpen] = React.useState(true);

  const menu: MenuItem[] = [
    {
      link: `/project/${projectCode}/dashboard`,
      title: t("workspace.menu.dashboard"),
      icon: DashboardMenuIcon,
    },
    {
      link: `/project/${projectCode}/configuration`,
      title: t("workspace.menu.configuration"),
      icon: ConfigMenuIcon,
    },
  ];

  async function focusMainWindow() {
    const all = await getAllWebviewWindows();
    const mainWin = all.find((w) => w.label === "main");
    if (mainWin) {
      await mainWin.setFocus();
      await mainWin.show();
    }
  }

  const sidebarProps: SidebarProps = {
    title: projectCode,
    menu,
    open: sidebarOpen,
    onToggle: () => setSidebarOpen((o) => !o),
    onNavigate: (link) => navigate({ to: link }),
    footer: (
      <Button
        size="small"
        variant="outlined"
        fullWidth
        onClick={() => void focusMainWindow()}
      >
        {t("workspace.focusMain")}
      </Button>
    ),
  };

  return (
    <Box sx={{ display: "flex", minHeight: "100vh" }}>
      <Sidebar {...sidebarProps} />
      <Box component="main" sx={{ flexGrow: 1, transition: "margin 0.3s" }}>
        <Outlet />
      </Box>
    </Box>
  );
}
```

## Cross-window settings sync

### `src/data/settings.ts` (new)

```ts
import { useEffect } from "react";
import { load, type Store } from "@tauri-apps/plugin-store";
import { useThemeMode, type ThemeMode } from "@aegis/ui/theme";
import { useI18n, type Locale } from "@aegis/ui/i18n";

let storePromise: Promise<Store> | null = null;
async function getStore(): Promise<Store> {
  if (!storePromise) storePromise = load("settings.bin");
  return storePromise;
}

/**
 * Read theme + locale from the on-disk settings store and apply them
 * to the React providers. Mounted once at the top of App in main.tsx
 * so every window picks up the user's last choice before its first
 * render.
 */
export function useHydrateSettingsFromStore() {
  const { mode, setMode } = useThemeMode();
  const { locale, setLocale } = useI18n();

  useEffect(() => {
    let cancelled = false;
    void (async () => {
      const store = await getStore();
      const theme = await store.get<ThemeMode>("theme");
      const loc = await store.get<Locale>("locale");
      if (cancelled) return;
      if (theme && theme !== mode) setMode(theme);
      if (loc && loc !== locale) setLocale(loc);
    })();
    return () => {
      cancelled = true;
    };
    // intentionally empty deps: this runs once per window mount
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);
}

/**
 * Subscribe to live changes broadcast by the main window. Mounted
 * once per window alongside the hydration hook.
 */
export function useListenForSettingsChanges() {
  const { setMode } = useThemeMode();
  const { setLocale } = useI18n();
  useEffect(() => {
    let unlisten: (() => void) | null = null;
    void (async () => {
      const { listen } = await import("@tauri-apps/api/event");
      const u = await listen<{ theme?: ThemeMode; locale?: Locale }>(
        "aegis:settings-changed",
        ({ payload }) => {
          if (payload.theme) void setMode(payload.theme);
          if (payload.locale) void setLocale(payload.locale);
        },
      );
      unlisten = u;
    })();
    return () => {
      if (unlisten) unlisten();
    };
  }, [setMode, setLocale]);
}

/** Imperative write used by PersistentThemeProvider /
 *  PersistentI18nProvider (defined in SettingsSyncBridge.tsx). */
export async function persistSettings(patch: {
  theme?: ThemeMode;
  locale?: Locale;
}) {
  const store = await getStore();
  if (patch.theme !== undefined) await store.set("theme", patch.theme);
  if (patch.locale !== undefined) await store.set("locale", patch.locale);
  await store.save();
}
```

### `src/SettingsSyncBridge.tsx` (new)

The bridge has three responsibilities:

1. Pass `onModeChange` / `onLocaleChange` callbacks to the providers
   that persist the change to `tauri-plugin-store` AND broadcast an
   `aegis:settings-changed` event.
2. On mount, hydrate the providers' values from the on-disk store
   (so a freshly-opened workspace window reflects the user's last
   choice before its first paint).
3. Subscribe to `aegis:settings-changed` events for live updates from
   other windows.

```tsx
import {
  useHydrateSettingsFromStore,
  useListenForSettingsChanges,
  persistSettings,
} from "./data/settings";
import { type ThemeMode, AegisThemeProvider } from "@aegis/ui/theme";
import { AegisI18nProvider, type Locale } from "@aegis/ui/i18n";
import { emit } from "@tauri-apps/api/event";

/**
 * Glue component mounted once per window. Hydrates theme + locale
 * from the on-disk store, then subscribes to live changes. Also
 * exposes the persist+emit hook to the providers via their
 * onModeChange / onLocaleChange callback props — the bridge wraps
 * the providers' providers in main.tsx.
 */
export function SettingsSyncBridge({
  children,
}: {
  children: React.ReactNode;
}) {
  useHydrateSettingsFromStore();
  useListenForSettingsChanges();
  return <>{children}</>;
}

/**
 * Wrap AegisThemeProvider so every setMode call in any window gets
 * persisted + broadcast. Lives in this file because it is the only
 * desktop-side consumer of the provider's onModeChange hook.
 */
export function PersistentThemeProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  const handleChange = async (mode: ThemeMode) => {
    await persistSettings({ theme: mode });
    await emit("aegis:settings-changed", { theme: mode });
  };
  return (
    <AegisThemeProvider onModeChange={handleChange}>
      {children}
    </AegisThemeProvider>
  );
}

/**
 * Wrap AegisI18nProvider so every setLocale call in any window gets
 * persisted + broadcast.
 */
export function PersistentI18nProvider({
  children,
  defaultLocale,
}: {
  children: React.ReactNode;
  defaultLocale?: "en" | "zh-CN";
}) {
  const handleChange = async (locale: Locale) => {
    await persistSettings({ locale });
    await emit("aegis:settings-changed", { locale });
  };
  return (
    <AegisI18nProvider
      onLocaleChange={handleChange}
      defaultLocale={defaultLocale}
    >
      {children}
    </AegisI18nProvider>
  );
}
```

Notes:
- `@aegis/ui/theme` and `@aegis/ui/i18n` already write to `localStorage`
  inside their own useEffect (per the `AegisThemeProvider` /
  `AegisI18nProvider` source). That localStorage is per-webview and
  not shared across windows — `tauri-plugin-store` is the cross-window
  authoritative source we add here.
- `onModeChange` / `onLocaleChange` are part of the existing
  `AegisThemeProviderProps` / `AegisI18nProviderProps` shapes. No
  provider changes are needed.
- The main window also fires the broadcast, but its own listener is a
  no-op (the local `setMode` already updated state). Workspace windows
  pick up the event and call their own `setMode` / `setLocale`.

### `src/main.tsx` (modified)

```tsx
import {
  PersistentThemeProvider,
  PersistentI18nProvider,
  SettingsSyncBridge,
} from "./SettingsSyncBridge";

function App() {
  React.useEffect(() => {
    requestAnimationFrame(() => {
      requestAnimationFrame(async () => {
        try {
          const win = getCurrentWindow();
          await win.show();
          await win.setFocus();
        } catch (err) {
          console.error("[App] Failed to show window:", err);
        }
      });
    });
  });
  return (
    <React.StrictMode>
      <PersistentThemeProvider>
        <QueryProvider>
          <PersistentI18nProvider>
            <SettingsSyncBridge>
              <DocumentLangSync />
              <RouterProvider router={router} />
              {import.meta.env.DEV && (
                <TanStackRouterDevtools
                  router={router}
                  position="bottom-right"
                />
              )}
            </SettingsSyncBridge>
          </PersistentI18nProvider>
        </QueryProvider>
      </PersistentThemeProvider>
    </React.StrictMode>
  );
}
```

`SettingsSyncBridge` must live INSIDE both `PersistentThemeProvider`
and `PersistentI18nProvider` — it calls `useThemeMode` and `useI18n`,
which read from those providers' React contexts. `QueryProvider` sits
between theme and i18n to match the existing layering (theme provides
the MUI context that wraps everything).

The `bootstrap` URL rewrite in `main.tsx` already short-circuits when
the pathname is anything other than `/` or `/index.html` — workspace
windows land on `/project/<code>` and skip the rewrite cleanly.

`Settings.tsx` is **unchanged** — the persistence + broadcast happens
via the provider callbacks, so every call site (today: only Settings,
future: any code that calls `setMode` / `setLocale`) gets cross-window
sync for free.

## Error handling

| Failure | Surface |
|---|---|
| `WebviewWindow.new` throws (e.g. label collision race) | `onOpenWorkspace` swallows; the row click is idempotent on retry. Snackbar/Toast out of scope. |
| Workspace window: project does not exist | Window loads; Dashboard renders placeholder. Existence check is out of scope (deferred). |
| Workspace window: `useCurrentUser` fails (e.g. expired token) | The workspace pages do not consume `useCurrentUser` — placeholders render normally. The user clicks "Back to main" to refocus the main window for re-login. |
| Close-on-logout: one `w.close()` rejects | Other closes still proceed; `qc.clear()` is in a separate `await` line so it runs even if `Promise.all` rejects. |
| `emit("aegis:settings-changed")` with no listeners | Resolves successfully; no throw path. |
| `load("settings.bin")` throws | Hydration skips; window keeps in-memory defaults. No crash. |
| `getAllWebviewWindows` rejects on logout | `qc.clear()` is not reached (the awaited promise rejected). `UserFooter` calls `mutateAsync` which surfaces the error in `mutation.error`. The user can retry — no auth boundary is crossed in the meantime. |

## Out of scope (deferred to a later feature)

- The actual Dashboard / Configuration content — both are placeholders.
- Project-existence check in `_project/route.tsx` (`api.getProjectByCode`
  + 404 placeholder).
- Workspace window auto-refresh on token expiry (would mirror the
  main window's session-refresh flow).
- Per-project layout overrides.
- Snackbar/Toast for `openProjectWorkspace` failures.
- Window position/size persistence on reopen (`tauri-plugin-window-state`).
- IPC: workspace window reading or mutating project data. The
  placeholder pages consume no APIs.

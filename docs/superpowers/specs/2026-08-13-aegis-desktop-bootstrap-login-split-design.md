# Aegis Desktop: split splash into bootstrap + login

Date: 2026-08-13
Status: Drafted (brainstorming)

## Goal

Split the current `SplashPage` so that the pre-app health check and
login-status probe live on their own page, and the login UI lives on a
separate page. The result clarifies responsibilities — the bootstrap
page either redirects to `/login` or to `/` (home), and never exposes
login UI itself.

## Scope

In scope:

- New `BootstrapPage` (`pages/bootstrap.tsx`) and `/bootstrap` route.
- New `LoginPage` (`pages/login.tsx`) and `/login` route, holding the
  login UI that previously lived on the splash.
- The auth guard on `_layout` redirects to `/login` instead of `/splash`.
- `main.tsx` sets the initial location to `/bootstrap` via
  `history.replaceState`.
- `SplashLog` component is renamed to `BootstrapLog` (folder, files,
  exports, hooks, prop types).
- i18n keys: `splash.*` is renamed to `login.*` (login UI) and
  `bootstrap.*` (bootstrap UI). New `bootstrap.*` keys for the login
  status step.
- Existing splash tests are split into `bootstrap.test.tsx` and
  `login.test.tsx`.

Out of scope:

- Any change to the Tauri backend (`login`, `login_domain`, `healthz`,
  `is_logged_in`).
- Any change to the register page (`/register`).
- The flicker guard from `b1d8e14`.
- Persistence of login state across restarts.
- A retry affordance on the bootstrap page (per requirement: failures
  stop the flow with no recovery action).

## Routing

```
src/routes/
  __root.tsx              unchanged
  bootstrap.tsx           NEW  -> /bootstrap
  login.tsx               NEW  -> /login
  register.tsx            unchanged
  _layout/route.tsx       MODIFIED: redirect target /splash -> /login
  _layout/index.tsx       unchanged (/)
  _layout/settings.tsx    unchanged (/settings)
```

`/bootstrap` and `/login` are siblings of `_layout`, not children, so
they render without the Sidebar chrome.

After the deletion of `routes/splash.tsx`, the `routeTree.gen.ts` is
regenerated by `@tanstack/router-plugin` and committed alongside.

### Entry redirect

The app starts at `/bootstrap`. This is set in `main.tsx` before
`createRouter`:

```ts
if (
  window.location.pathname === "/" ||
  window.location.pathname === "/index.html"
) {
  window.history.replaceState(null, "", "/bootstrap");
}
const router = createRouter({ routeTree });
```

If `replaceState` is a no-op in the Tauri webview (the `tauri://`
protocol is unusual), the fallback is to call
`router.navigate({ to: "/bootstrap", replace: true })` immediately after
`createRouter` instead. The detection is `window.location.pathname`
after the call: if it still equals the original value, do the navigate.

### Auth guard

`_layout/route.tsx` becomes:

```ts
beforeLoad: async () => {
  let loggedIn = false;
  try {
    loggedIn = await api.isLoggedIn();
  } catch {
    loggedIn = false;
  }
  if (!loggedIn) {
    throw redirect({ to: "/login" });
  }
}
```

Same behaviour as before: a broken `isLoggedIn` (token-store error)
counts as logged out, so the user lands on `/login` rather than seeing
the router throw.

## `BootstrapPage` flow

The page mounts at `/bootstrap`. Its single job is to check the server
and the session, then redirect.

### On mount

1. `push("info", "bootstrap.log.healthCheck.start")`
2. `await api.healthz()`
3. success → `push("success", "bootstrap.log.healthCheck.ok", { status })`
4. failure → `push("error", "bootstrap.log.healthCheck.failed", { message })`.
   Render the stepper with `<StepLabel error>` on step 0. **No retry.
   The user must restart the app or fix the server.**

The `useRef` StrictMode guard from the current splash is ported here so
the health check fires only once.

### After health success

5. `push("info", "bootstrap.log.loginStatus.start")`
6. `let loggedIn = false; try { loggedIn = await api.isLoggedIn(); } catch {}`
7. logged in → `push("success", "bootstrap.log.loginStatus.ok")` →
   `navigate({ to: "/" })` (replace)
8. not logged in → `push("info", "bootstrap.log.loginStatus.notLoggedIn")` →
   `navigate({ to: "/login" })` (replace)
9. `isLoggedIn` throws → `push("error", "bootstrap.log.loginStatus.failed", { message })`.
   Render the stepper with `<StepLabel error>` on step 1. **No retry.**

The login-status check uses the same exception-swallowing pattern as the
`_layout` guard, so a token-store failure is treated as "not logged in"
and the user lands on `/login`.

### UI

A vertical `Stepper` with two steps, mirroring the current splash stepper
visually:

- `bootstrap.step.health` — labelled with the health status.
- `bootstrap.step.loginStatus` — labelled with the login-status status.

State `activeStep` defaults to `0` and advances to `1` once `healthz()`
resolves. Step 1's `<StepLabel error>` is set when the health check fails
(stop on step 0) or when `isLoggedIn()` throws (stop on step 1). On
either error, the navigation in steps 7–8 does **not** fire — the user
sees only the error step plus the log.

`<BootstrapLog>` renders below the stepper, mirroring the existing
audit trail. The page header reads `bootstrap.title`.

The bootstrap page does **not** render any login UI. There is no method
choice, no form, no submit button. If the user is not logged in, they
arrive on `/login` immediately after step 8.

## `LoginPage` flow

The body of the current `SplashPage` minus the health check, the first
step, and the `healthStarted` ref. No functional change.

### State

`method` (default `"domain"`), `accountCode`, `password`, `inFlight`,
`outcome` (`"none" | "notFound" | "inactive" | "failed"`). Identical
to the current splash.

### Method step

A `RadioGroup` with two `FormControlLabel` options — `domain` and
`account`. Switching methods clears `outcome` so a stale alert does not
linger. The account fields render only when `account` is selected.

### Submission

```ts
if (method === "domain") {
  void runLogin(() => api.loginDomain());
} else {
  void runLogin(() => api.login(accountCode, password));
}
```

`loginDisabled` is `inFlight || (method === "account" && (!accountCode || !password))`.

### Outcomes

| Outcome | Behaviour |
|---|---|
| resolves | `push("success", "login.log.login.ok")`, then `navigate({ to: "/" })` |
| `http` + `not_found` | `push("error", "login.log.login.notFound")`; render the hint with a **Register** button that navigates to `/register` |
| `http` + `user_inactive` | `push("error", "login.log.login.inactive")`; render the admin hint. No register button. |
| everything else | `push("error", "login.log.login.failed", { message })`. Dead stop. |

The login page does **not** run a health check — the bootstrap page has
guaranteed it succeeded before the user reaches here.

## `RegisterPage` flow

### New `bootstrap.*` keys

| Key | English | Simplified Chinese |
|---|---|---|
| `bootstrap.title` | `Welcome to Aegis` | `欢迎使用 Aegis` |
| `bootstrap.step.loginStatus` | `Checking login status` | `正在检查登录状态` |
| `bootstrap.log.loginStatus.start` | `Checking login status...` | `正在检查登录状态……` |
| `bootstrap.log.loginStatus.ok` | `Already logged in. Entering the app...` | `已登录，正在进入应用……` |
| `bootstrap.log.loginStatus.notLoggedIn` | `Not logged in. Continuing to login...` | `未登录，正在进入登录页……` |
| `bootstrap.log.loginStatus.failed` | `Login status check failed: {message}` | `登录状态检查失败：{message}` |

The `bootstrap.log.loginStatus.failed` key is new and only emitted when
`isLoggedIn()` throws. The same exception in the `_layout` guard does
not log anything — it just redirects. The `bootstrap.log.loginStatus.failed`
behaviour is therefore reachable only when the `_layout` guard bypasses
the bootstrap (e.g. a deep link to `/` followed by an `isLoggedIn`
throw). The spec keeps the log entry for visibility in that rare case.

### Unchanged

- `register.*`, `app.*`, `nav.*`, `home.*`, `settings.*`, `language.*`.

The `bootstrap.log.loginStatus.ok` text differs from `login.log.login.ok`:
one is "already logged in", the other is "just logged in". They are
distinct outcomes and deserve distinct keys.

## Migration order

The key renames let the project compile at every step, so the migration
is incremental and each step is verifiable.

1. Add `bootstrap.*` and `login.*` keys to `en.ts` and `zhCN.ts`. Keep
   `splash.*` keys; the old code still uses them.
2. Create `pages/login.tsx` as a copy of `pages/splash.tsx` minus the
   health check; switch its strings to `login.*` keys.
3. Create `routes/login.tsx` pointing at `LoginPage`.
4. Create `pages/bootstrap.tsx` with the new health + login-status flow
   using `bootstrap.*` keys.
5. Create `routes/bootstrap.tsx` pointing at `BootstrapPage`.
6. Rename `SplashLog` → `BootstrapLog` (folder, files, exports, hook,
   prop types). Update `data-testid` values. Update imports in
   `bootstrap.tsx`, `login.tsx`, `register.tsx`, and the still-living
   `pages/splash.tsx` (which is deleted in step 9).
7. Update `_layout/route.tsx` redirect target from `/splash` to `/login`.
8. Update `main.tsx` to set initial location to `/bootstrap` via
   `history.replaceState` (with the navigate fallback).
9. Delete `pages/splash.tsx` and `routes/splash.tsx`. Remove the old
   `splash.*` keys from `en.ts` and `zhCN.ts`.
10. Rename `test/routes/splash.test.tsx` → `test/routes/login.test.tsx`
    with the key / testid updates; create `test/routes/bootstrap.test.tsx`.
11. Regenerate `routeTree.gen.ts` (commit alongside).

## Rejected alternatives

| Alternative | Why rejected |
|---|---|
| One page that toggles between "bootstrap" and "login" modes | Requires reading state from the URL to decide which mode to render in, which is what the router is for. |
| `main.tsx` initial location via `createRouter({ initialLocation: ... })` | Not a supported option in TanStack Router v1; the supported path is `RouterProvider`'s initial location or `history.replaceState` before `createRouter`. |
| `_layout` guard redirects to `/bootstrap` instead of `/login` | Splits the "I am not logged in" decision across two places: the guard and the bootstrap page. The guard's job is to keep unauthenticated users out of `_layout`; once they are redirected to `/login`, the bootstrap-then-login flow is self-contained. |
| Move the home page to `/home` | Breaks muscle memory and bookmarks for no behavioural gain. |
| Keep `SplashLog` as the component name | The user explicitly requested the rename. The component is used by bootstrap, login, and register; the new name reflects the broader role. |
| Translate `bootstrap.log.loginStatus.ok` identical to `login.log.login.ok` | The two outcomes are semantically different ("already logged in" vs "just logged in") and can be distinguished in the locale. |
| Retry button on the bootstrap page | Contradicts the stated "failures stop the flow with no recovery action" requirement. |
| Single `isLoggedIn` check (in bootstrap only) | Removing the `_layout` guard breaks the safety net for direct links to `/` and `/settings`. The duplication is cheap. |

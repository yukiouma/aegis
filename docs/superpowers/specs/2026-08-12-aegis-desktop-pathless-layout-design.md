# Aegis Desktop — Pathless Layout Route — Design

**Date:** 2026-08-12
**Status:** Approved (pending spec review)
**Scope:** Move the Sidebar + main-`<Box>` chrome currently in `src/routes/__root.tsx` into a TanStack Router **pathless layout route** (`_layout.tsx`). `__root.tsx` becomes a bare `<Outlet />`. The two existing page routes (`/`, `/settings`) are moved into a `_layout/` directory so they are children of the new pathless layout. This is a pure structural refactor — rendered DOM, behavior, and tests' assertions are unchanged.

---

## 1. Goals

1. Lift the application chrome (Sidebar + main pane) out of `__root.tsx` and into a dedicated pathless layout route.
2. Make future routes able to opt out of the chrome by simply *not* being placed under `_layout/` (e.g., a future `/login` page without a Sidebar).
3. Leave `__root.tsx` as a one-line `<Outlet />`, matching the conventional TanStack Router pattern.
4. Preserve all current behavior: Sidebar collapse/expand, navigation, theme/i18n wiring, Tauri invoke calls — all unchanged.
5. Keep all existing tests passing with the same assertions, after renaming the layout test to follow the new file.

---

## 2. URL map (unchanged)

| Path         | Route file                          | Component       |
| ------------ | ----------------------------------- | --------------- |
| `/`          | `src/routes/_layout/index.tsx`      | `HomePage`      |
| `/settings`  | `src/routes/_layout/settings.tsx`   | `SettingsPage`  |
| `*`          | (TanStack default)                  | `NotFound`      |

The pathless layout (`_layout`) contributes **no URL segment** — `/` and `/settings` continue to be top-level paths.

**Note on file naming:** TanStack Router's directory-based pathless-layout convention requires the layout component to live in `route.tsx` *inside* the `_layout/` directory — not as `_layout.tsx` at the parent level alongside the directory. The plugin treats `route.tsx` as the layout route for sibling files in the same directory.

## 5. `routes/__root.tsx` — slim root

```tsx
import { createRootRoute, Outlet } from "@tanstack/react-router";

export const Route = createRootRoute({
  component: () => <Outlet />,
});
```

- No `Box`, no `Sidebar`, no theme/i18n imports — those move to `_layout.tsx`.
- The route name (`__root.tsx`) and TanStack semantics (always the root) are unchanged.

---

## 6. `routes/_layout/route.tsx` — pathless layout

```tsx
import React from "react";
import { createFileRoute, Outlet, useNavigate } from "@tanstack/react-router";
import { Box } from "@aegis/ui/mui";
import { Sidebar, type MenuItem, type SidebarProps } from "@aegis/ui";
import { Home as HomeIcon, Settings as SettingsIcon } from "@aegis/ui/icons";
import { useI18n } from "@aegis/ui/i18n";

const HomeMenuIcon = () => <HomeIcon />;
const SettingsMenuIcon = () => <SettingsIcon />;

export const Route = createFileRoute("/_layout")({
  component: AppLayout,
});

export default function AppLayout() {
  const { t } = useI18n();
  const navigate = useNavigate();
  const [sidebarOpen, setSidebarOpen] = React.useState(true);

  const menu: MenuItem[] = [
    { link: "/", title: t("nav.home"), icon: HomeMenuIcon },
    { link: "/settings", title: t("nav.settings"), icon: SettingsMenuIcon },
  ];

  const sidebarProps: SidebarProps = {
    title: t("app.title"),
    menu,
    open: sidebarOpen,
    onToggle: () => setSidebarOpen((o) => !o),
    onNavigate: (link) => navigate({ to: link }),
  };

  return (
    <Box sx={{ display: "flex", minHeight: "100vh" }}>
      <Sidebar {...sidebarProps} />
      <Box
        component="main"
        sx={{
          flexGrow: 1,
          ml: `${sidebarOpen ? 240 : 56}px`,
          transition: "margin 0.3s",
        }}
      >
        <Outlet />
      </Box>
    </Box>
  );
}
```

- The function is renamed from `RootLayout` to `AppLayout` to avoid confusion with the `__root.tsx` route. (The route's URL `/` and `/settings` are unchanged; only the layout's *internal* function name moves.)
- All other imports, state, and JSX are byte-identical to the current `__root.tsx`.
- `createFileRoute("/_layout")` registers the pathless layout route. The plugin matches the underscore prefix and treats it as a layout with no URL contribution.

## 7. Child route files (byte-identical bodies)

### 7.1 `routes/_layout/index.tsx`

```tsx
import { createFileRoute } from "@tanstack/react-router";
import { HomePage } from "../../pages/home";

export const Route = createFileRoute("/_layout/")({
  component: HomePage,
});
```

- The `createFileRoute` path argument is `/_layout/` — TanStack Router matches it as a child of the `/_layout` pathless layout at the `/` URL.
- `HomePage` import moves from `"../pages/home"` to `"../../pages/home"` to account for the deeper directory.

### 7.2 `routes/_layout/settings.tsx`

```tsx
import { createFileRoute } from "@tanstack/react-router";
import { SettingsPage } from "../../pages/settings";

export const Route = createFileRoute("/_layout/settings")({
  component: SettingsPage,
});
```

- Same shift in the import path (`"../pages/settings"` → `"../../pages/settings"`).
- URL `/settings` is preserved by the `/_layout` parent contributing no segment.

---

## 8. Generated routeTree shape (after plugin regen)

The plugin will produce a tree that wires:

- `__root__` → `_layout` (pathless) → `/` (`HomePage`)
- `__root__` → `_layout` (pathless) → `/settings` (`SettingsPage`)

Concretely, the regenerated `routeTree.gen.ts` will declare `_layout` as the `getParentRoute` for both child routes (replacing today's `rootRouteImport`). This is automatic — no manual edit to the generated file.

## 10. Behavior (unchanged)

- **Initial render:** App boots at `/`. The pathless layout renders the Sidebar; its `<Outlet />` renders `HomePage`. Sidebar is open.
- **Navigation:** clicking a Sidebar menu item → `onNavigate(link)` → `navigate({ to: link })` → the layout's `<Outlet />` swaps to the matching child route. No remount of the Sidebar (it lives in `_layout.tsx`).
- **Sidebar collapse:** local `sidebarOpen` state in `AppLayout` toggles the main pane's `margin-left` (240 ↔ 56). No route change.
- **Settings / Home behavior:** identical to today (theme switch, locale switch, login form, Tauri `invoke` calls).
- **Tauri invoke:** unchanged.
- **Devtools:** `TanStackRouterDevtools` continues to render in dev (mounted in `main.tsx`); unaffected by this refactor.

## 12. Import discipline (carry-over)

`aegis-desktop` depends on `@aegis/ui` only — never import `@mui/material` or `@mui/icons-material` directly. The new `_layout.tsx` follows this rule (same imports as today's `__root.tsx`).

---

## 13. Out of scope

- Adding new routes (e.g., a no-Sidebar `/login` route is a possible follow-up that *benefits* from this refactor but is not part of it).
- Type-safe route params or search-param typing.
- A custom `NotFound` page.
- Modifying `@aegis/ui`'s Sidebar.
- Any Tauri-side change.
- Server-side data loaders (`loader`, `beforeLoad`) — not needed for static pages.
- Auth-guarded routes.

# Aegis Desktop splashscreen: login + register pages

Date: 2026-08-13
Status: Approved (brainstorming)

## Goal

Give the desktop app a pre-app splashscreen that guides the user through a
server health check, a login-method choice, and login — or, when the user
has no account yet, on to a registration page. Every step prints a log line
on the page so the user can see exactly where the flow stopped.

## Scope

In scope:

- Two new frontend routes: `/splash` and `/register`.
- An auth guard on the existing `_layout` route.
- An app-local log panel component and its state hook.
- An `ApiError` narrowing helper shared by both pages.
- A backend change: `login_domain` no longer takes a `code` parameter.
- A backend fix: `Identity` serializes as camelCase, matching its TS type.
- New `splash.*` / `register.*` i18n keys in `en` and `zhCN`.

Out of scope:

- A separate Tauri `WebviewWindow` splashscreen. Rejected in brainstorming
  in favour of in-app routes, which need no Rust/config changes and are
  covered by the existing vitest route harness.
- Retry affordances for failed steps. Per the requirement, failures stop
  the flow with no recovery action (the sole exception is `not_found`,
  which offers a Register button).
- Any change to the server's `/api/auth/login-domain` wire contract.

## Architecture

### Routing

```
src/routes/
  __root.tsx            unchanged
  splash.tsx            NEW  -> /splash
  register.tsx          NEW  -> /register
  _layout/route.tsx     MODIFIED: beforeLoad guard
  _layout/index.tsx     unchanged (/)
  _layout/settings.tsx  unchanged (/settings)
```

`/splash` and `/register` are siblings of `_layout`, not children, so they
render without the Sidebar chrome.

`routeTree.gen.ts` is generated by `@tanstack/router-plugin` and will pick
up the new files automatically on the next dev/build run. It is committed
to the repo, so the regenerated file must be committed alongside the new
routes.

### Auth guard

`_layout/route.tsx` gains:

```ts
export const Route = createFileRoute("/_layout")({
  beforeLoad: async () => {
    let loggedIn = false;
    try {
      loggedIn = await api.isLoggedIn();
    } catch {
      loggedIn = false;
    }
    if (!loggedIn) throw redirect({ to: "/splash" });
  },
  component: AppLayout,
});
```

One guard covers `/` and `/settings` and every future page under the
layout. `api.isLoggedIn()` throwing (a token-store error) is treated as
"not logged in" rather than propagated, so a broken store sends the user
to the splash instead of crashing the router.

### Units

| Unit | Purpose | Depends on |
|---|---|---|
| `useSplashLog()` | Append-only log state; `push(level, key, params?)` | React only |
| `<SplashLog>` | Renders entries, translating at render time | `useI18n`, MUI |
| `toApiError` / `httpCode` | Narrow the unknown rejection value to `ApiError` | `api/types` |
| `SplashPage` | Health check → method choice → login | api, hook, component, router |
| `RegisterPage` | Identity lookup → form → register | api, hook, component |

## Components

### `src/api/error.ts`

Tauri rejects with the serialized `ApiError` object (`{ kind, ... }`).
Both pages need to branch on the HTTP `code`, so the narrowing lives in
one place rather than being duplicated.

```ts
import type { ApiError } from "./types";

export function toApiError(e: unknown): ApiError {
  if (
    typeof e === "object" && e !== null && "kind" in e &&
    typeof (e as { kind: unknown }).kind === "string"
  ) {
    return e as ApiError;
  }
  return { kind: "network", message: String(e) };
}

export function httpCode(e: unknown): string | null {
  const err = toApiError(e);
  return err.kind === "http" ? err.code : null;
}

export function errorMessage(e: unknown): string {
  const err = toApiError(e);
  switch (err.kind) {
    case "network": return err.message;
    case "http": return `${err.code}: ${err.message}`;
    case "refreshFailed": return "refresh failed";
    case "notImplemented": return err.detail;
    case "store": return err.message;
  }
}
```

A non-`ApiError` rejection (a thrown JS `Error`, a string) degrades to
`{ kind: "network", message: String(e) }` so `httpCode` returns `null`
and the caller takes the generic-failure branch.

### `src/components/SplashLog/`

```
SplashLog.tsx       component
useSplashLog.ts     hook
types.ts            LogLevel, LogEntry
index.ts            re-exports
```

```ts
export type LogLevel = "info" | "success" | "error";

export interface LogEntry {
  id: number;
  level: LogLevel;
  key: string;
  params?: Record<string, string>;
}
```

`useSplashLog()` returns `{ entries, push }`. `push` takes
`(level, key, params?)` and appends with a monotonically increasing `id`
from a ref (no `Date.now()`, no array index, so React keys stay stable).
`push` is wrapped in `useCallback` with an empty dep list so it is safe in
`useEffect` dependency arrays.

Entries store the **translation key and params, not translated text**, so
switching language re-renders existing log lines in the new language.
`SplashLog` calls `t(entry.key, entry.params)` at render.

Level → MUI colour: `info` → `text.secondary`, `success` → `success.main`,
`error` → `error.main`. The container is a `Paper` with `variant="outlined"`,
`maxHeight: 200`, `overflowY: auto`, monospace `Typography` rows, and
`data-testid="splash-log"`.

App-local rather than in `@aegis/ui`: only the splash and register pages
use it, and putting it in the shared package would mean shared-package
tests, exports, and i18n keys for a single-consumer component.

## Splash page flow

MUI `Stepper` (`orientation="vertical"`), `activeStep` from state, three
steps. A failed step gets `<StepLabel error>`.

### Step 0 — Health check

Runs automatically on mount via `useEffect`. A `useRef` boolean guards
against React StrictMode's double-invoke so `healthz` is not called twice.

1. `push("info", "splash.log.healthCheck.start")`
2. `await api.healthz()`
3. success → `push("success", "splash.log.healthCheck.ok")`, `setActiveStep(1)`
4. failure → `push("error", "splash.log.healthCheck.failed", { message })`,
   `setFailed(true)`. The stepper stays on step 0 and nothing further
   renders. No retry.

### Step 1 — Method selection

A `RadioGroup` with two `FormControlLabel` options — `account` and
`domain` — and a Continue button. Continue logs
`splash.log.method.selected` (with the localized method name) and sets
`activeStep = 2`.

### Step 2 — Credentials

Rendered conditionally on the step-1 choice:

- **account**: `code` and `password` (`type="password"`) `TextField`s plus
  a Login button, disabled while either is empty or a request is in
  flight. Calls `api.login(code, password)`.
- **domain**: no input at all. A single "Login with domain" button calling
  `api.loginDomain()` — no argument, because the Rust command now reads
  the OS identity itself (see below). The splash therefore does **not**
  call `getDomainUserInfo`.

An `inFlight` state disables the submit button during the request so a
double-click cannot fire two logins.

### Result handling

Both paths funnel into one `handleLoginResult`:

| Outcome | Behavior |
|---|---|
| resolves | `push("success", "splash.log.login.ok")`, then `navigate({ to: "/" })` |
| `http` + `not_found` | `push("error", "splash.log.login.notFound")`; render hint text and a **Register** button navigating to `/register` |
| `http` + `user_inactive` | `push("error", "splash.log.login.inactive")`; render "contact your administrator" hint. Dead stop. |
| everything else | `push("error", "splash.log.login.failed", { message: errorMessage(e) })`. Dead stop. |

"Everything else" covers `invalid_credentials`, `network`,
`notImplemented` (domain login on a non-Windows host), `store`, and
`refreshFailed`.

## Register page

On mount (same StrictMode ref guard):

1. `push("info", "register.log.identity.start")`
2. `await api.getDomainUserInfo()`
3. success → `push("success", "register.log.identity.ok")`, store the
   `Identity` in state
4. failure → `push("error", "register.log.identity.failed", { message })`.
   The form never renders. Dead stop.

Once the identity resolves, six `TextField`s render:

| Field | Value | Editable |
|---|---|---|
| `userCode` | `identity.userid` | no (`disabled`) |
| `domainName` | `identity.domain` | no (`disabled`) |
| `hostname` | `identity.hostMachine` | no (`disabled`) |
| `sid` | `identity.sid` | no (`disabled`) |
| `userName` | user input | yes |
| `password` | user input (`type="password"`) | yes |

The Register button is disabled until both editable fields are non-empty,
and while a request is in flight. It calls:

```ts
api.registerUser({
  userCode: identity.userid,
  userName,
  domainName: identity.domain,
  hostname: identity.hostMachine,
  sid: identity.sid,
  password,
})
```

- **Success** → `push("success", "register.log.register.ok")` and an
  `<Alert severity="info">` reading "Registration submitted. Contact your
  administrator to activate your account." The form is replaced by the
  alert so it cannot be submitted twice. **Dead end — no navigation
  offered.**
- **Failure** → `push("error", "register.log.register.failed",
  { message: errorMessage(e) })`. Dead stop.

## Backend fix: `Identity` serializes as camelCase

Tauri v2 auto-converts camelCase **command arguments** from JS to
snake_case Rust parameters, so `api.registerUser({ userCode, ... })`
correctly reaches `register_user(user_code: String, ...)`. It does **not**
rename **return values**.

`system::identity::Identity` derives `Serialize` with no `rename_all`, so
`get_domain_user_info` currently returns:

```json
{ "domain": "...", "host_machine": "...", "sid": "...", "userid": "..." }
```

while `src/api/types.ts` declares the field as `hostMachine`. Reading
`identity.hostMachine` yields `undefined`, and the register page would
silently submit `hostname: undefined`. The register page cannot be built
correctly without resolving this.

Fix — in `src-tauri/src/system/identity.rs`:

```rust
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
#[serde(rename_all = "camelCase")]
pub struct Identity { /* unchanged */ }
```

The TS `Identity` interface needs no change; it becomes accurate. The
server contract is untouched: `http::auth::login_domain` builds
`LoginDomainRequest` from `Identity`'s **Rust fields**, and
`LoginDomainRequest` has its own snake_case serialization, so nothing
about the outbound HTTP body changes.

A Rust test asserts `serde_json::to_string(&Identity { .. })` contains
`"hostMachine"`, locking the wire shape against regression.

The same mismatch exists on other response DTOs (`RegisterUserResponse`,
`UserView`, `ProductView`, `ProjectView` — all snake_case on the wire,
camelCase in TS). Fixing them is **out of scope**: this design only reads
`Identity` fields and the boolean success of `registerUser`, never the
register response's fields. The file-top comment in `api/types.ts` is
updated to note that `Identity` is now genuinely camelCase while the
others are not yet.

## Backend change: `login_domain` drops its `code` parameter

The user code passed to `login_domain` was always going to be the OS
identity's `userid`; requiring the frontend to supply it duplicated a
value the Rust side already reads. The server's request body is
**unchanged** — `code`, `domain_name`, `hostname`, `sid` are all still
sent. Only the source of `code` moves from the caller to
`identity::current()`.

### `src-tauri/src/http/auth.rs`

```rust
pub async fn login_domain(c: &HttpClient) -> Result<(), ApiError> {
    let id = identity::current()?;
    let body = LoginDomainRequest {
        code: id.userid,
        domain_name: id.domain,
        hostname: id.host_machine,
        sid: id.sid,
    };
    // ... unchanged from here
}
```

Note the second change on that line: the existing
`.map_err(|_| ApiError::NotImplemented { detail: "loginDomain requires
Windows" })` swallows genuine Windows lookup failures (which
`identity::current()` returns as `ApiError::Store`) into a misleading
"requires Windows" message. Since `identity::current()` already returns
`ApiError`, the `map_err` is replaced by `?`, propagating the real error.
This is a one-line fix in code the change already touches.

### `src-tauri/src/commands/auth.rs`

```rust
#[tauri::command]
pub async fn login_domain(client: State<'_, HttpClient>) -> Result<(), ApiError> {
    auth::login_domain(&client).await
}
```

### `src/api/index.ts`

```ts
loginDomain: (): Promise<void> => call<void>("login_domain"),
```

`call` already handles `args === undefined` by invoking without an args
object, so no wrapper change is needed.

## i18n

New keys go into **both** `lib/packages/ui/src/i18n/locales/en.ts` and
`zhCN.ts`. The locale registry has a compile-time key-parity check, so a
key missing from `zhCN` is a typecheck failure, not a runtime fallback.

Key groups:

- `splash.title`, `splash.step.health`, `splash.step.method`,
  `splash.step.credentials`
- `splash.method.account`, `splash.method.domain`, `splash.method.continue`
- `splash.field.code`, `splash.field.password`, `splash.action.login`,
  `splash.action.loginDomain`, `splash.action.register`
- `splash.hint.inactive`, `splash.hint.notFound`
- `splash.log.healthCheck.start|ok|failed`, `splash.log.method.selected`,
  `splash.log.login.start|ok|failed|notFound|inactive`
- `register.title`, `register.field.*`, `register.action.register`,
  `register.hint.contactAdmin`
- `register.log.identity.start|ok|failed`,
  `register.log.register.start|ok|failed`

Messages carrying a server error use a `{message}` parameter, matching the
existing `{name}` / `{mode}` interpolation style in the locale files.

## Rejected alternatives

| Alternative | Why rejected |
|---|---|
| Separate Tauri splashscreen `WebviewWindow` | Requires Rust and `tauri.conf.json` changes and is invisible to the vitest route harness. In-app routes get the same UX for less machinery. |
| Splash at `/`, home moved to `/app` | Churns existing route paths and their tests for no behavioural gain over a `_layout` guard. |
| No auth guard | Nothing would stop an unauthenticated user reaching the app pages. |
| `SplashLog` in `@aegis/ui` | Single consumer; shared-package ceremony without shared-package benefit. |
| Translating log text at `push` time | Entries logged before a language switch would stay in the old language. |
| Retry buttons on failed steps | Contradicts the stated "stop there without any action by default". |
| Auto-redirect to `/register` on `not_found` | The user would not see why they were moved. |
| Register as a fourth stepper step | Register needs its own identity lookup and lifecycle; a separate route keeps each page's flow linear. |
| A confirm-password field on register | The requirement specifies exactly two editable fields. |
| "Back to login" after successful register | The account cannot be used until an admin activates it, so returning to login would only reproduce the same failure. |
| Fixing `Identity` casing in TS instead of Rust | Would make `Identity` the only snake_case interface among the camelCase TS types. Renaming in Rust keeps TS uniform and makes the existing type accurate. |
| Casting `(identity as any).host_machine` at the call site | Preserves a type that lies about its own wire shape. |
| Fixing camelCase on all response DTOs | Out of scope; this design reads no fields from any response DTO other than `Identity`. |

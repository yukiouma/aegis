# Aegis Desktop — TanStack Router File-Based Routing Refactor — Design

**Date:** 2026-08-11
**Status:** Approved (pending spec review)
**Scope:** Replace the manual `useState<Page>` page-switching in `aegis-desktop`'s `App.tsx` with `@tanstack/react-router` in file-based routing mode. Reorganise the frontend around a `routes/` directory and migrate all tests to a `test/` directory with a `renderInRouter` / `renderWithFullRouter` helper following the official [test file-based routing](https://tanstack.com/router/latest/docs/how-to/test-file-based-routing.md) guide.

---

## 1. Goals

1. Adopt TanStack Router with the `@tanstack/router-plugin/vite` plugin (already installed and configured) in file-based routing mode.
2. Replace the `useState<Page>` switch in `App.tsx` with route-driven navigation via `useNavigate` from `@tanstack/react-router`.
3. Reorganise the frontend so each route lives in its own file under `src/routes/`, with the layout (Sidebar + main pane) in `__root.tsx`.
4. Migrate all tests to `src/test/`, with a shared `file-route-utils.tsx` exporting `renderInRouter` (leaf component) and `renderWithFullRouter` (full layout) helpers, per the TanStack official testing guide.
5. Keep the existing UI behaviour identical: Home at `/`, Settings at `/settings`, sidebar collapse/expand unchanged, theme + language toggles unchanged, Tauri `greet` command unchanged.

---

## 2. URL map

| Path         | Route file                  | Component           |
| ------------ | --------------------------- | ------------------- |
| `/`          | `src/routes/index.tsx`      | `HomePage`          |
| `/settings`  | `src/routes/settings.tsx`   | `SettingsPage`      |
| `*`          | (TanStack default)          | `NotFound` fallback |

The Home menu's `link` in the Sidebar changes from `"/home"` to `"/"` to match the new path. The Settings link stays `"/settings"`.

## 5. `main.tsx` — entry point

```tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { AegisI18nProvider } from "@aegis/ui/i18n";
import { AegisThemeProvider } from "@aegis/ui/theme";
import { createRouter, RouterProvider } from "@tanstack/react-router";
import { routeTree } from "./routes/routeTree.gen";
import { DocumentLangSync } from "./DocumentLangSync";

const router = createRouter({ routeTree });

declare module "@tanstack/react-router" {
  interface Register {
    router: typeof router;
  }
}

ReactDOM.createRoot(document.getElementById("root") as HTMLElement).render(
  <React.StrictMode>
    <AegisThemeProvider>
      <AegisI18nProvider>
        <DocumentLangSync />
        <RouterProvider router={router} />
      </AegisI18nProvider>
    </AegisThemeProvider>
  </React.StrictMode>,
);
```

- `createRouter({ routeTree })` is called once at module load.
- The `Register` interface module augmentation enables full type inference for `Link`, `useNavigate`, and route params across the app.
- `<DocumentLangSync/>` stays above `<RouterProvider/>` (its current placement) so the `<html lang>` sync runs on every locale change regardless of route.
- `autoCodeSplitting: true` is already enabled in `vite.config.ts`; the plugin splits each route into its own chunk automatically.

## 6. `routes/__root.tsx` — layout

```tsx
import React from "react";
import { Outlet, useNavigate } from "@tanstack/react-router";
import { Box } from "@aegis/ui/mui";
import { Sidebar, type MenuItem, type SidebarProps } from "@aegis/ui";
import { Home as HomeIcon, Settings as SettingsIcon } from "@aegis/ui/icons";
import { useI18n } from "@aegis/ui/i18n";

const HomeMenuIcon = () => <HomeIcon />;
const SettingsMenuIcon = () => <SettingsIcon />;

export default function RootLayout() {
  const { t } = useI18n();
  const navigate = useNavigate();
  const [sidebarOpen, setSidebarOpen] = React.useState(true);

  const menu: MenuItem[] = [
    { link: "/", title: t("nav.home"), icon: HomeMenuIcon },
    { link: "/settings", title: t("nav.settings"), icon: SettingsMenuIcon },
  ];

  const sidebarProps: SidebarProps = {
    title: t("app.title"),
    menu,
    open: sidebarOpen,
    onToggle: () => setSidebarOpen((o) => !o),
    onNavigate: (link) => navigate({ to: link }),
  };

  return (
    <Box sx={{ display: "flex", minHeight: "100vh" }}>
      <Sidebar {...sidebarProps} />
      <Box
        component="main"
        sx={{
          flexGrow: 1,
          ml: `${sidebarOpen ? 240 : 56}px`,
          transition: "margin 0.3s",
        }}
      >
        <Outlet />
      </Box>
    </Box>
  );
}
```

- The Sidebar from `@aegis/ui` is **unchanged** — it still receives an `onNavigate(link: string)` callback. The layout owns that callback and calls `useNavigate()` from `@tanstack/react-router`.
- `sidebarOpen` state stays local to `RootLayout` (sidebar collapse does not navigate).
- `<Outlet/>` replaces the old `{page === "settings" ? <SettingsPage/> : <HomePage/>}` ternary.

## 7. Route components

### 7.1 `routes/index.tsx`

```tsx
import { createFileRoute } from "@tanstack/react-router";
import { useState } from "react";
import { Box, Button, Stack, Typography } from "@aegis/ui/mui";
import { useI18n } from "@aegis/ui/i18n";
import { invoke } from "@tauri-apps/api/core";

export const Route = createFileRoute("/")({
  component: HomePage,
});

function HomePage() {
  const { t } = useI18n();
  const [greetMsg, setGreetMsg] = useState("");

  async function testGreet() {
    setGreetMsg(await invoke<string>("greet", { name: "Aegis" }));
  }

  return (
    <Box sx={{ p: 4 }}>
      <Typography variant="h4" gutterBottom>{t("home.heading")}</Typography>
      <Typography variant="body1" sx={{ mb: 3 }}>{t("home.welcome")}</Typography>
      <Stack direction="row" spacing={2} sx={{ alignItems: "center" }}>
        <Button variant="contained" onClick={testGreet}>{t("home.testGreet")}</Button>
        {greetMsg && <Typography variant="body2">{greetMsg}</Typography>}
      </Stack>
    </Box>
  );
}
```

### 7.2 `routes/settings.tsx`

```tsx
import { createFileRoute } from "@tanstack/react-router";
import type { ChangeEvent } from "react";
import {
  Box,
  FormControl,
  FormControlLabel,
  InputLabel,
  MenuItem,
  Select,
  Switch,
  Typography,
  type SelectChangeEvent,
} from "@aegis/ui/mui";
import { useI18n, type Locale } from "@aegis/ui/i18n";
import { useThemeMode } from "@aegis/ui/theme";

export const Route = createFileRoute("/settings")({
  component: SettingsPage,
});

function SettingsPage() {
  const { mode, setMode } = useThemeMode();
  const { locale, setLocale, t } = useI18n();

  const handleThemeChange = (event: ChangeEvent<HTMLInputElement>) => {
    setMode(event.target.checked ? "dark" : "light");
  };
  const handleLanguageChange = (event: SelectChangeEvent<Locale>) => {
    setLocale(event.target.value as Locale);
  };

  const themeLabel = t("settings.theme.label", {
    mode: t(mode === "dark" ? "settings.theme.dark" : "settings.theme.light"),
  });

  return (
    <Box sx={{ p: 4, display: "flex", flexDirection: "column", gap: 2 }}>
      <Typography variant="h4" gutterBottom>{t("settings.heading")}</Typography>
      <FormControlLabel
        control={<Switch checked={mode === "dark"} onChange={handleThemeChange} />}
        label={themeLabel}
      />
      <FormControl size="small" sx={{ minWidth: 160 }}>
        <InputLabel id="language-label">{t("settings.language.label")}</InputLabel>
        <Select<Locale>
          labelId="language-label"
          value={locale}
          label={t("settings.language.label")}
          onChange={handleLanguageChange}
        >
          <MenuItem value="en">{t("language.english")}</MenuItem>
          <MenuItem value="zh-CN">{t("language.simplifiedChinese")}</MenuItem>
        </Select>
      </FormControl>
    </Box>
  );
}
```

The page bodies are byte-equivalent to today's `HomePage.tsx` / `SettingsPage.tsx` — only the file location and the `createFileRoute(...)` declaration change.

## 8. Devtools

`@tanstack/react-router-devtools` is already a dev dependency. Wire it in `main.tsx`, dev-only, so it doesn't ship to production:

```tsx
import { TanStackRouterDevtools } from "@tanstack/react-router-devtools";

// inside <RouterProvider/> via children is the supported pattern:
//   <RouterProvider router={router}>
//     <Outlet />
//     {import.meta.env.DEV && <TanStackRouterDevtools position="bottom-right" />}
//   </RouterProvider>
```

Because `autoCodeSplitting: true` makes `<RouterProvider/>` render a lazy `<Outlet/>` internally, the cleanest pattern is to drop the devtools directly under `<RouterProvider/>` in `main.tsx`:

```tsx
<RouterProvider router={router} />
{import.meta.env.DEV && <TanStackRouterDevtools position="bottom-right" />}
```

`import.meta.env.DEV` is replaced at build time by Vite, so the devtools are stripped from production bundles.

## 9. Test helper — `src/test/file-route-utils.tsx`

```tsx
import { ReactNode } from "react";
import {
  createMemoryHistory,
  createRootRoute,
  createRoute,
  createRouter,
  Outlet,
  RouterProvider,
} from "@tanstack/react-router";
import { render, type RenderOptions } from "@testing-library/react";
import { routeTree } from "../routes/routeTree.gen";

interface RenderInRouterOptions extends Omit<RenderOptions, "wrapper"> {
  initialEntries?: string[];
}

/**
 * Render a component in a minimal router at "/" — for testing a single page
 * in isolation (no real layout, no Sidebar). Use `renderWithFullRouter` to
 * exercise the full `__root.tsx` layout and navigation.
 */
export function renderInRouter(
  ui: ReactNode,
  { initialEntries = ["/"], ...renderOptions }: RenderInRouterOptions = {},
) {
  const history = createMemoryHistory({ initialEntries });

  const rootRoute = createRootRoute({
    component: () => <Outlet />,
  });

  const indexRoute = createRoute({
    getParentRoute: () => rootRoute,
    path: "/",
    component: () => <>{ui}</>,
  });

  const router = createRouter({
    routeTree: rootRoute.addChildren([indexRoute]),
    history,
  });

  return {
    ...render(<RouterProvider router={router} />, renderOptions),
    router,
  };
}

interface RenderWithFullRouterOptions extends Omit<RenderOptions, "wrapper"> {
  initialEntries?: string[];
}

/**
 * Render the full app routeTree (including `__root.tsx` layout) with an
 * in-memory history. Use this for tests that exercise the Sidebar, layout,
 * or navigation between real routes.
 */
export function renderWithFullRouter({
  initialEntries = ["/"],
  ...renderOptions
}: RenderWithFullRouterOptions = {}) {
  const history = createMemoryHistory({ initialEntries });
  const router = createRouter({ routeTree, history });

  return {
    ...render(<RouterProvider router={router} />, renderOptions),
    router,
  };
}
```

- `renderInRouter` is the leaf helper — wrap a component in a minimal `Outlet`-only tree at `/`. Used by `routes/index.test.tsx` and `routes/settings.test.tsx`.
- `renderWithFullRouter` mounts the real `routeTree` from `routeTree.gen.ts`. Used by `routes/__root.test.tsx` to test Sidebar + navigation.
- Both return the router instance so tests can assert on `router.state.location.pathname` after navigation.
- Wrapping providers (`AegisThemeProvider`, `AegisI18nProvider`) are applied by individual test files as needed (the helpers do not impose them).

| Test file | Helper used | What it covers |
| --- | --- | --- |
| `src/test/routes/index.test.tsx` | `renderInRouter(<HomePage/>)` | Greet button invokes `invoke('greet', { name: 'Aegis' })`; renders the welcome copy. |

If a fourth test file needs them, extract a `renderWithProviders` helper then.

## 12. Behaviour

- **Initial render:** App boots at `/`. Sidebar open. `routes/index.tsx` (Home) renders inside the `<Outlet/>`.
- **Navigation:** clicking a Sidebar menu item → `onNavigate(link)` → `navigate({ to: link })` → `<Outlet/>` swaps to the matching route component. No remount of the Sidebar (it lives in `__root.tsx`).
- **Sidebar collapse:** clicking the toggle icon flips local `sidebarOpen` state; the main pane's `margin-left` animates (240 ↔ 56). No route change.
- **Settings behaviour:** theme + language toggles work identically to today; `useThemeMode` and `useI18n` are unchanged; `DocumentLangSync` continues to mirror locale to `<html lang>`.
- **Tauri invoke:** clicking `Test greet` on Home calls the Rust `greet` command (unchanged) and renders the response.
- **404:** TanStack's default NotFound page renders for any unmatched path (acceptable for a desktop app — no custom 404 page planned).
- **Devtools:** `TanStackRouterDevtools` renders at the bottom-right in dev builds only; stripped from production by `import.meta.env.DEV`.

## 14. Import discipline (carry-over from prior spec)

`aegis-desktop` depends on `@aegis/ui` only — never import `@mui/material` or `@mui/icons-material` directly. Always go through:

- `@aegis/ui/mui` for MUI components.
- `@aegis/ui/icons` for MUI icons.
- `@aegis/ui` for the package's own exports.
- `@aegis/ui/i18n`, `@aegis/ui/theme` for provider-specific hooks.

The new route files and tests follow this rule.

## 15. Out of scope

- New routes beyond `/` and `/settings`.
- Type-safe route params (no dynamic segments yet).
- Search-param typing on the routes.
- Custom `NotFound` page.
- Modifying `@aegis/ui`'s Sidebar.
- A Tauri-side change. The Rust `greet` command is untouched.
- Server-side data loaders (`loader`, `beforeLoad`) — not needed for static pages.
- Auth-guarded routes — auth flows are a future sub-project.
- Removing `App.css` followups beyond the file deletion in §3.3.
